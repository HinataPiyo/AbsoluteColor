# ゲーム仕様

## 1. 操作

| 操作 | 動作 |
|---|---|
| R/G/B スライダー | 各色成分を0.0～1.0の範囲で調整。スライダー値は即座にプレビュー画面と採点対象の回答色に反映される |
| 決定ボタン | 現在のRGB値を回答色として確定。採点処理へ遷移 |
| ラウンド結果の「次へ」ボタン | ラウンド結果UIを閉じて次のラウンドへ進む |
| 総合結果の「ホーム」ボタン | ホーム画面シーンを読み込む |
| 総合結果の「リトライ」ボタン | ゲームプレイシーンを再読み込み |

操作はUI Toolkitのイベント（スライダーのchangeイベント、ボタンのclickedイベント）で処理される。Input SystemパッケージとActionsアセットは含まれるが、ゲームスクリプトから参照されていない。

## 2. ラウンド進行

- **総ラウンド数** — 5ラウンド
- **見本色生成** — 各ラウンドでR/G/B値を個別にランダムに生成（0～1の範囲）
- **制限時間** — 初回ラウンド15秒。以降、各ラウンドで前ラウンドの0.9倍
- **回答確定** — 決定操作または時間切れで確定
- **採点処理** — 色差計算から得点算出まで同一の処理フロー
- **ラウンド結果表示** — UIパネルが表示されている間、GameManager のCoroutineで待機
- **総合結果** — 5ラウンド終了後に表示

## 3. 採点

### 色差の計算

見本色 T = (Tr, Tg, Tb)、回答色 A = (Ar, Ag, Ab) とするとき、色差 d は：

```
d = (|Ar - Tr| + |Ag - Tg| + |Ab - Tb|) / 3
```

RGB各成分の絶対差を平均した単純な距離度量。Lab色空間やΔE値などの知覚色差は使用していない。

### 判定（Judgment Type）

色差 d に基づいて判定を決定：

| 判定 | 条件 | 説明 |
|---|---|---|
| Perfect | d < 0.05 | ほぼ完全に一致 |
| Excellent | d < 0.15 | 高い精度で一致 |
| Great | d < 0.30 | 良好な精度で一致 |
| Good | d < 0.50 | 一定の精度で一致 |
| Bad | d ≥ 0.50 | 低い精度、大きく異なる |

### 得点計算

```
score = round(750 × Lerp(1.75, 0.1, d))
```

- MaxScore = 750
- 最大係数 = 1.75（d = 0 のとき）
- 最小係数 = 0.1（d = 1.0 のとき）
- 完全一致（d = 0）時のスコア：round(750 × 1.75) = **1313点/ラウンド**
- 完全不一致（d = 1.0）時のスコア：round(750 × 0.1) = **75点/ラウンド**

### 割合表示

```
percentage = (1 - d) × 100
```

0～100の範囲で表示。d = 0 のとき100%、d = 1.0 のとき0%。

### スコアランク

5ラウンドの合計スコアから総合ランクを判定。基準は正規化値を使用：

```
normalized = total_score / (5 × 750 × 1.75)
```

ランク判定（降順で評価）：

| ランク | 条件 | 説明 |
|---|---|---|
| S | normalized ≥ 0.95 | 95%以上の正規化値 |
| A | normalized ≥ 0.90 | 90%以上の正規化値 |
| B | normalized ≥ 0.70 | 70%以上の正規化値 |
| C | normalized ≥ 0.80 | 80%以上の正規化値 |
| D | normalized < 0.80 | その他 |

**注**: 現在の実装ではB（≥0.70）の判定がC（≥0.80）より先に評価されるため、Cランクに到達できない。改善計画の優先度P0を参照。

## 4. UI とシーン

### ホーム画面（HomeScene）

- 色チャンネル一覧（ColorChannelDataSO配列から表示）
- 色チャンネル選択パネル
- RGB プレビューエリア（選択中のデータでRGBプレビュー表示）
- スコア履歴パネル（最大100件、CoreResourceのStackから取得）
- 音量調整スライダー（BGM/SEの各ボリューム）
- ゲーム開始ボタン

### ゲームプレイ画面（GamePlayScene）

**情報表示エリア**：
- ラウンド番号
- 残り制限時間（秒単位）
- 見本色（球体で表示）

**操作エリア**：
- R/G/Bスライダー（値0.0～1.0）
- 調整中の色プレビュー
- 決定ボタン

**結果表示エリア**：
- ラウンド結果パネル（見本色、回答色、得点、判定）
- 判定テキスト（JugementUI）
- 総合結果パネル（AllRoundTotalResult）

## 5. データ管理

### 編集時データ

**ColorChannelDataSO**：色チャンネル関連情報
- 説明テキスト
- 表示名
- マテリアル（プレビュー表示用）

**AudioDataSO**：音声クリップ管理
- タグ（"GamePlayScene", "SpawnTopic" など）
- AudioClipの参照

### 実行時データ

**CoreResource（静的）**：
- 選択中のColorChannelDataSO参照
- スコア履歴（Stack、最大100件）
- 色チャンネルごとの最高得点

**ResultData**：
- TopicColor（見本色）
- AnswerColor（回答色）
- RoundCount（ラウンド番号）

ファイルシステムまたはPlayerPrefsへの永続化処理はない。アプリ再起動後にデータは失われる。

## 6. シーン構成

Build Settingsに登録：
- HomeScene（0）
- GamePlayScene（1）

遷移フロー：
- HomeScene → ゲーム開始操作 → GamePlayScene読み込み
- GamePlayScene → 総合結果「ホーム」 → HomeScene読み込み
- GamePlayScene → 総合結果「リトライ」 → GamePlaySceneを再読み込み

## 7. 外部連携

### Unityroom ランキング送信

`AllRoundTotalResult.ShowAllRoundResult()` 内で `UnityroomApiClient.Instance.SendScore()` を呼び出し、合計スコアをランキングボードに送信。通信結果の確認やエラーハンドリングは実装されていない。

### Input System

Input System 1.19.0パッケージが含まれ、`InputSystem_Actions.inputactions`アセットが存在するが、ゲームスクリプトから参照されておらず、UI Toolkitイベントのみで操作を処理している。
