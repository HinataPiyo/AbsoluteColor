# ゲーム仕様書（実装確認版）

本書は確認できたコード・設定を仕様として整理する。未実装・未確認の項目は「未確認」と記載し、企画上の希望を実装済み仕様として扱わない。

## 1. 操作方法

| 操作 | 実装上の挙動 |
|---|---|
| R/G/Bスライダー | それぞれの色成分を0〜1の範囲で調整する。変更値を保持し、調整色のプレビューへ反映する。 |
| 決定ボタン | 現在の調整値で回答を確定し、ラウンド結果へ進む。 |
| 結果画面の次へ | 結果表示を閉じ、待機しているゲーム進行を次ラウンドへ進める。 |
| 最終結果のホーム／リトライ | ホームシーン、またはゲームプレイシーンを再読込する。 |

UI Toolkit上のスライダー・ボタンのコールバックで操作する。入力アクションアセットには汎用のPlayer／UIアクションが定義されているものの、`Assets/Scripts`からInput System APIまたは同アセットを参照するコードは確認できない。したがって、ゲーム操作はInput Actions経由ではなく、UI Toolkitイベントとして実装されている。マウス／タッチ等の各ターゲットでの実機検証は未確認。

## 2. ラウンド進行

- 1ゲームは `ValueConstants.MaxRound` の5ラウンド。
- 各ラウンド開始時、R/G/B成分を個別にランダム生成して見本色に設定する。
- 制限時間は初回15秒。ラウンド番号を `n` とすると `15 × 0.9^(n-1)` 秒。
- 決定操作で待ち時間を終了する。時間切れの場合も現時点の値を回答として採点する。
- 結果表示中はオーバーレイを表示して入力を遮る。
- 次へ操作で結果パネルを閉じ、進行コルーチンを再開する。
- 5ラウンド終了後、総合結果へ進む。

上記の時間式はコード上の値であり、実時間の誤差・フレーム更新の影響を含むプレイテスト結果ではない。

## 3. 色合わせと採点

回答色を `A=(Ar,Ag,Ab)`、見本色を `T=(Tr,Tg,Tb)` としたとき、コードは各成分の差の平均を色差として扱う。

```text
difference = (|Ar-Tr| + |Ag-Tg| + |Ab-Tb|) / 3
percentage = (1 - difference) × 100
score = round(750 × Lerp(1.75, 0.1, difference))
```

各色成分が0〜1なら色差は0〜1の範囲を想定した式である。`ResultData.GetDifferenceByColor()`は各チャンネルの符号付き差も求め、`GetDifferenceByValue()`は平均絶対誤差を返す。判定閾値は次のとおり。

| 判定 | 色差 |
|---|---:|
| Perfect | `< 0.05` |
| Excellent | `< 0.15` |
| Great | `< 0.30` |
| Good | `< 0.50` |
| Bad | `0.50以上` |

**既知の仕様上の注意**：`MaxScore` は750だが、色差0では得点係数1.75を掛けるため、整数化前の1ラウンド得点は1312.5となる。総合ランク計算では分母にも1.75を掛けているため、750は基準値として使われている。定数名とUI表示上の意味が「1ラウンドの上限」を指すのかは要確認。さらに、ランク判定の条件順によりCランクは到達不能である。

総合ランクは `totalScore / (MaxRound × MaxScore × 1.75)` を割合として、S: `>=0.95`、A: `>=0.90`、B: `>=0.70`、C: `>=0.80`、それ以外Dの順に判定する。C条件はB条件より後にあるため、`>=0.80`の値は先にBへ分類される。

## 4. プレイヤー・敵・スキル

- **プレイヤー**：色を調整するUI操作主体。移動、HP、攻撃等のアクションは確認できない。
- **敵／NPC**：ゲーム上の敵・NPC行動システムは確認できない。
- **スキル／成長**：スキル、経験値、恒久成長要素は確認できない。
- **敗北条件**：独立した敗北状態は確認できない。時間切れはその時点の調整値を提出する処理である。Bad判定は最低評価であり、ゲーム終了条件ではない。

## 5. モード・ステージ・Wave

- `ColorChannelDataSO` は色チャンネル関連のモード情報（説明、名前、マテリアル等）を保持する。
- ステージ選択、複数ステージ遷移、Wave／スポーン管理は確認できない。
- アセットの具体的な登録数とモード選択肢の網羅性は、SOのシリアライズ内容で確認できる範囲に限られる。

## 6. UIと演出

- ホーム画面：モード選択、RGB色プレビュー、スコア履歴、オプション、プレイ開始に関するUIがある。
- ホームにはCollection／Event／Rankingのボタン参照もあるが、クリック動作の接続は確認できない。意図された機能は未確認。
- ゲーム画面：ラウンド表示、見本色、調整スライダー／プレビュー、決定、ラウンド結果、総合結果。
- 結果演出：判定テキスト、効果音、カメラ揺れ、Bloom/Vignette等のポストプロセス、最終ランクに応じたパーティクル。
- ラウンド結果表示には見本色・回答色のプレビュー、各チャンネルの色差表示が含まれる。
- UIパネルの表示切り替えには `hide-panel`／`show-panel` のUSSクラスが利用される。
- 視認性・アクセシビリティ・画面サイズ別の操作品質は実機で未検証。

## 7. スコア履歴・音量・外部送信

- スコア履歴はメモリ上の静的コレクションで管理され、表示は最大100件。履歴項目のクリックコールバック登録には不具合があり、期待するクリック動作は保証されない。
- 高得点・選択モード・音量等について、アプリ再起動をまたぐ永続化は確認できない。
- ゲーム終了時にオンラインランキング送信を呼び出すコードがある。外部サービス側の設定、認証、通信成否、オフライン時の挙動は未確認。
- BGM/SEはタグとクリップを `AudioDataSO` に登録し、`AudioManager` 経由で再生する。

## 8. シーン遷移・終了

Build Settingsに登録されたシーンは `Assets/Scenes/HomeScene.unity`、`Assets/Scenes/GamePlayScene.unity` の2つ。ホームからプレイへ進み、最終結果からホームまたはプレイシーン再読込へ遷移する。アプリ終了・中断・復帰に関するゲーム固有処理は未確認。
